# Threat Model

Scope: risks specific to an automated performance-regression detector that feeds
engineering decisions. The tool has no network access, no LLM in the decision
path, and runs on user-supplied telemetry.

## 1. Hallucination / overclaiming

- **Risk**: reporting a regression that isn't real, or asserting a root cause.
- **Mitigations**:
  - Verdicts are pure deterministic functions of the data; no generative text
    invents findings.
  - A `REGRESSION`/`IMPROVEMENT` finding **cannot be constructed without
    evidence** (`RegressionFinding` model validator). Enforced by
    `test_regression_without_evidence_is_rejected`.
  - The tool never claims root cause; it links artifacts for human investigation.
    README and every Markdown report state this explicitly.

## 2. Unsafe assumptions (false negatives / false positives)

- **Risk**: treating noise as a regression, or masking a regression with noise.
- **Mitigations**:
  - Dual significance gate (effect size **and** robust z) prevents flagging small
    noisy wiggles (`test_no_false_alarm_on_noise_group`).
  - Robust (MAD/IQR) statistics prevent a single wild sample from creating or
    hiding a regression (`test_fpga_outlier_does_not_cause_false_regression`).
  - Low-sample large changes are `INCONCLUSIVE`, not silently `STABLE`
    (`test_low_samples_large_change_is_inconclusive_not_regression`).
  - Comparisons are **controlled**: runs on different platforms/tool-versions are
    never paired (`test_incomparable_runs_not_compared_across_platforms`).

## 3. Comparing apples to oranges

- **Risk**: attributing a platform/tool-version change to a code regression.
- **Mitigation**: grouping key includes `environment.fingerprint()` (platform +
  tool@version). Different environments form different groups and are not
  compared.

## 4. Data leakage / confidential content

- **Risk**: shipping proprietary telemetry, internal hostnames, or paths.
- **Mitigations**:
  - Bundled data is synthetic mock telemetry generated by a seeded function;
    artifact URLs point at `example.org`.
  - No secrets or credentials are read; CI needs none.
  - `extra="forbid"` means the schema won't silently carry unexpected fields.

## 5. Reproducibility risks

- **Risk**: non-deterministic output undermining trust and golden tests.
- **Mitigations**:
  - Standard-library-only statistics (no numpy version skew).
  - Seeded benchmark; golden JSON + Markdown committed and tested for drift.
  - Reports embed the `detection_config` and `schema_version` used.

## 6. Schema drift

- **Risk**: consuming telemetry from an incompatible producer.
- **Mitigation**: `schema_version` is validated on load; a mismatched major
  version raises (`test_run_rejects_incompatible_major_schema`).

## Residual risks (accepted for v0.1)

- Only first-vs-last comparison per group; an intermediate transient regression
  that recovers by the newest commit is not separately flagged.
- Thresholds are global defaults; per-metric tuning is a future phase.
- Confidence is a bounded heuristic score, not a calibrated probability.
